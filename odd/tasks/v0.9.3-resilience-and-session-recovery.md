# Feature: v0.9.3 resilience and session recovery

## Objective
Prepare the fork's next `0.9.3` version by fixing the audited updater/UI/runtime regressions, preventing malformed provider tool calls from becoming durable session events, and recovering readable history from a semantically corrupt log tail without modifying its source. The recovered prefix must reach the product as an explicitly read-only view with a localized warning, and future runtime process launch sites must be covered by a fail-closed headless contract.

## Problem and why
The v0.9.2 audit found a false-positive DSH update affordance when no current runtime version is known, an opaque square backing surface behind the otherwise circular update button, an unbounded upstream fetch, synchronous runtime extraction on Electron's main thread, permissive native ABI validation, and contract-test child processes that do not request hidden windows. Separately, a malformed pi-ai tool-call stream can emit empty correlation IDs; the agent then persists assistant/tool events that make the whole v4 history fail lifecycle validation. The user's affected session has 1,249 valid events followed by two syntactically valid but semantically corrupt records. Storage recovery exposes the valid prefix, but the higher-level resume path takes write ownership first, so the prefix has no verified read-only presentation path. The packaged headless verifier also enumerates known launchers rather than detecting new child-process call sites. Preserve the current running application and the original history file.

## Scope and constraints
- Work only on the fork in this repository; do not change or merge upstream.
- Keep the user's currently running FreeCode instance untouched: do not inspect, close, restart, install over, launch a replacement, or kill it or any unrelated process. The ordinary release gate is non-interactive at the FreeCode UI boundary, not process-free: it may start only test-owned hidden DSH CLI/Electron-as-Node and repository fixture children in scratch, with loopback mocks and no maintainer credentials or third-party MCP code. Cleanup may target only a test-owned PID tree; never enumerate processes or terminate by image name. The gate may build and statically inspect packages but never install/launch the GUI or regenerate the pinned runtime. Interactive installer smoke is VM-only and separate from this workstation gate.
- The user has authorized publishing v0.9.3 to the fork `Akunimal/free-code-deepseek-harness` using the previously authorized `gh` session: align English/Spanish release docs, build final isolated Windows x64 setup and portable artifacts, push release commits fast-forward-only to `main`, create/push tag `v0.9.3`, and publish the GitHub release with setup, portable, blockmap, and `latest.yml`. Do not modify or merge upstream. Preserve the older `release-0.9.3-local` outputs and do not regenerate the pinned DSH runtime tarball.
- Do not mutate the affected session under `%APPDATA%`; recovery must be read-only and preserve source bytes. A recovered history must not be writable/appended accidentally.
- User-selected recovery UX: show the valid prefix in read-only mode with an English/Spanish warning that reports omitted-event count and first invalid sequence; block resume/send/write. Do not offer or create a fork in this change.
- Update the root/app release metadata and bilingual v0.9.3 notes; do not modify historical release evidence.
- Engram mirror `odd/v0.9.3-resilience-and-session-recovery/tasks` is pending: runtime session identity is not registered, so agent-attributed memory writes are prohibited. Keep this file as the authoritative local recovery record until registration is available.

## Acceptance criteria
- Ordinary updater checks do not advertise a DSH runtime update when its installed version is unknown; the packaged first-run exact-version bootstrap still works.
- The update indicator's native/web surface remains transparent and its action visibly round. Upstream update requests have a finite timeout.
- DSH archive extraction is asynchronous and does not block Electron's main event loop; any timeout cleanup can only target the child created for extraction.
- Native ABI verification skips foreign-platform artifacts explicitly and fails on any load failure for a native addon applicable to the packaged host. Contract-test child processes opt into hidden-window creation.
- Malformed/missing provider tool-call IDs or names fail before emitting chunks that could become durable; agent-loop regression proves no malformed `assistant/message`, `tool/call`, or `tool/result` is persisted.
- A syntactically valid but semantically corrupt session tail exposes only the validated history prefix with recovery diagnostics, leaves the original raw/Zstd file byte-identical, and refuses write-open/append rather than silently extending it.
- Root and shell app metadata agree on `0.9.3`; published release notes, changelog, and English/Spanish READMEs accurately identify `0.9.3` as released.
- The isolated release output contains verified Windows x64 NSIS setup and portable assets; the historical 0.9.2 output and DSH runtime archive remain untouched.
- No user instance/process or real session is touched. The ordinary release gate may run only test-owned hidden CLI/Electron-as-Node and fixture children under scratch paths; it does not inspect or mutate unrelated processes, install or launch the GUI, or regenerate the pinned runtime. Optional interactive installer smoke is not a gate and is limited to a disposable Windows VM/account with explicit opt-in. Only the named fork receives the authorized main/tag/release update; never push or merge upstream.
- Ordinary desktop packaging and its release gate never rebuild or overwrite the separately versioned DSH runtime archive; runtime archive generation is an explicit runtime-release action only.
- The ordinary gate statically validates the exact setup it builds and never invokes the interactive NSIS smoke. If a separate install/launch smoke is ever run, it must be explicitly opted into on a disposable Windows VM/account using the exact selected setup; it is not a workstation release check.
- The normal release gate is non-interactive at the GUI boundary, does not mutate per-user shortcuts/registry or start the GUI, and runs only repository-owned MCP stdio fixtures against a loopback mock provider in scratch-only state; it never downloads or executes third-party MCP package code. Cleanup is limited to recorded test-owned children. External MCP is not part of the release gate. Interactive NSIS smoke is separate, requires explicit disposable-environment opt-in, and is limited to a disposable VM/account.
- The vendored LLM package typecheck accepts identity-free request messages and no longer contains impossible content-block branches.
- The vendored settings form/field React component tests execute with a single deduplicated React module and pass without invalid-hook-call errors.
- A semantic-tail recovery reaches the real conversation/history surface as the valid prefix plus a localized warning with omitted count and first-invalid sequence; the recovered view is read-only and cannot resume/send/append.
- A fail-closed source/runtime process-launch inventory detects new Node child-process launch sites and requires an explicit hidden-window policy, with narrowly documented visible-UI exceptions; shipped headless behavior remains checked against packaged runtime artifacts.
