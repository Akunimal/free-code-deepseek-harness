# Feature: v0.9.3 resilience and session recovery

## Objective
Prepare the fork's next `0.9.3` version by fixing the audited updater/UI/runtime regressions, preventing malformed provider tool calls from becoming durable session events, and recovering readable history from a semantically corrupt log tail without modifying its source.

## Problem and why
The v0.9.2 audit found a false-positive DSH update affordance when no current runtime version is known, an opaque square backing surface behind the otherwise circular update button, an unbounded upstream fetch, synchronous runtime extraction on Electron's main thread, permissive native ABI validation, and contract-test child processes that do not request hidden windows. Separately, a malformed pi-ai tool-call stream can emit empty correlation IDs; the agent then persists assistant/tool events that make the whole v4 history fail lifecycle validation. The user's affected session has 1,249 valid events followed by two syntactically valid but semantically corrupt records. Preserve the current running application and the original history file.

## Scope and constraints
- Work only on the fork in this repository; do not change or merge upstream.
- Keep the user's currently running FreeCode instance untouched: do not launch, close, restart, inspect, install, or kill it or any unrelated process.
- Implement local source/tests/docs and local work-unit commits only. No push, tag, release, installer build, or install is authorized by this feature.
- Do not mutate the affected session under `%APPDATA%`; recovery must be read-only and preserve source bytes. A recovered history must not be writable/appended accidentally.
- Update the root/app release metadata and bilingual v0.9.3 notes; do not modify historical release evidence.
- Engram mirror `odd/v0.9.3-resilience-and-session-recovery/tasks` is pending: runtime session identity is not registered, so agent-attributed memory writes are prohibited. Keep this file as the authoritative local recovery record until registration is available.

## Acceptance criteria
- Ordinary updater checks do not advertise a DSH runtime update when its installed version is unknown; the packaged first-run exact-version bootstrap still works.
- The update indicator's native/web surface remains transparent and its action visibly round. Upstream update requests have a finite timeout.
- DSH archive extraction is asynchronous and does not block Electron's main event loop; any timeout cleanup can only target the child created for extraction.
- Native ABI verification skips foreign-platform artifacts explicitly and fails on any load failure for a native addon applicable to the packaged host. Contract-test child processes opt into hidden-window creation.
- Malformed/missing provider tool-call IDs or names fail before emitting chunks that could become durable; agent-loop regression proves no malformed `assistant/message`, `tool/call`, or `tool/result` is persisted.
- A syntactically valid but semantically corrupt session tail exposes only the validated history prefix with recovery diagnostics, leaves the original raw/Zstd file byte-identical, and refuses write-open/append rather than silently extending it.
- Root and shell app metadata agree on `0.9.3`; current release notes and changelog describe the verified changes in English and Spanish without claiming build/install/publication that did not happen.
- No user instance/process is touched; no app/installer is launched or built.
