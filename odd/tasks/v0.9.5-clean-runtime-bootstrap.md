# Feature: v0.9.5 clean-cache runtime proof and release-coder rule

## Objective
Ship v0.9.5 only after proving a first-time user can obtain and start the separately published DSH runtime from an empty cache, and permanently instruct future coders not to claim or publish an unverified fresh install.

## Problem and why
The v0.9.4 release includes the pinned alpha8 runtime asset and the application code attempts to download it when its per-user cache is absent. The user's successful local install required preloading alpha8, and no empty-cache download was observed. Existing release checks validate the local archive and packaged installer statically; their passing result does not prove the public GitHub lookup, download, digest validation, extraction, ABI compatibility, or CLI startup all work together for a new user.

## Scope and constraints
- Add a release-gate smoke using the built Electron-as-Node runtime, a newly created empty scratch cache/profile, the production DSH bootstrap/updater code, and the actual public pinned GitHub release asset. It must prove download, SHA-256 verification, extraction, manifest/ABI checks, and a hidden CLI `--help` startup; network failure or any mismatch fails closed.
- Add a regression contract that fails if the release plan drops or weakens the fresh-cache smoke, and a root `AGENTS.md` rule for future coders: mocks, preloaded caches, static hashes, and installer exit code are not fresh-install evidence; do not call a runtime-dependent release ready or publish it until the exact public first-run smoke passes. If blocked, disclose it and hold publication.
- Fix the previously deferred Pool Status overlay close button and add a regression test. The user had explicitly deferred this known issue to the next release; this v0.9.5 is that release.
- Align active v0.9.5 package/version metadata, English and Spanish release documentation, and release assets; retain v0.9.4 tag/release unchanged.
- No upstream edits, no release/tag rewrites, no touching or stopping a running FreeCode instance, and no executing/installing the new setup unless separately authorized. Test children must be isolated, hidden, and owned by the gate.
- Remote scope explicitly authorized by the user: push the completed changes to `Akunimal/free-code-deepseek-harness` `main`, create `v0.9.5`, and publish its public release using the current `gh` session. Do not use any upstream repository or credentials other than that authorized destination/session.
- Preserve pre-existing Graphify, vendor scratch, and unrelated task files; stage only this feature's intended files.
- Persistent Engram mirror `odd/v0.9.5-clean-runtime-bootstrap/tasks`: pending because the host has not registered an authoritative runtime session ID; do not make an agent-attributed MCP write. Keep this file authoritative and report the mirror limitation.

- Publication checks: inspect exact v0.9.5 tag target, upload and verify installer/portable/update metadata and bilingual notes, confirm release asset links and hashes. Do not execute the installer.

## Acceptance criteria
1. A release gate starts with a fresh empty runtime/profile directory and, through production updater/bootstrap code, downloads the exact ABI-compatible runtime from its actual public GitHub release, verifies the advertised SHA-256, extracts it, validates its manifest and ABI, and starts the downloaded CLI hidden successfully.
2. The release plan contains the smoke as a mandatory, non-optional release step; a contract test fails if it is omitted or run without Electron's ABI/environment.
3. Root coder instructions state that static validation, mocks, a preloaded cache, or setup exit code cannot be represented as a successful first install; public release is held until clean-cache proof exists.
4. Root and shell package versions and active bilingual v0.9.5 release documentation agree; v0.9.4 remains unchanged.
5. Required checks and exact v0.9.5 assets are verified; the changes are pushed to the authorized fork's `main`, tagged `v0.9.5`, and published there. The new installer is not installed/launched.
6. The Pool Status overlay's close button closes that window reliably without closing the main app, covered by an automated regression test.
