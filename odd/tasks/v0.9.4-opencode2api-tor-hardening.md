# Feature: v0.9.4 opencode2api update and Tor hardening

## Objective
Prepare the fork's v0.9.4 candidate with a current vendored opencode2api, preserve FreeCode's direct-first anonymous routing, make Tor startup/control safer and more reliable, and restore Gentle AI in the selectable mode roster.

## Problem and why
The current embedded gateway is based on upstream opencode2api v1.3.5, while upstream v1.3.8 addresses free-model probe/manual-selection behavior and canonical session identity issues relevant to the recent no-model failures. The fork also has a Tor manager that treats an open SOCKS port as bootstrap readiness, exposes an unauthenticated local ControlPort, and disables adaptive circuit-timeout learning while forcing a five-second timeout. These behaviors can advertise a route before Tor is usable, let another local process control Tor, and reject ordinary slow circuits.

## Scope and constraints
- Work only on this fork. Public upstream source tag `v1.3.8` is the dependency baseline; do not edit, push to, or merge into the upstream repository.
- Preserve the local FreeCode anonymous-pool policy: every request starts on direct and advances to Tor only after a non-2xx response within the same request. Reapply and test it after source sync.
- Improve Tor ControlPort authentication and actual bootstrap readiness; remove the over-aggressive fixed circuit timeout and safely format Windows torrc paths where covered by tests. Preserve the long circuit dirtiness interval used for stable model streams.
- Restore Gentle AI as an explicitly selectable Web agent mode, adapting its fork preset to the current declarative Web bundle and protecting the shipped selector path with regression tests. Standard remains the default.
- Do not inspect, close, restart, or kill unrelated processes. The user explicitly authorized generating and executing the local 0.9.4 one-click setup and confirmed FreeCode is closed before execution. Do not run a separate app launch or GUI smoke beyond any normal installer post-install action.
- Local source/tests/docs, embedded opencode2api binaries, electron-builder setup/portable artifacts, and execution of the generated local setup are authorized. Tag/release, push, `gh`, and all other remote changes remain unauthorized.
- Keep unrelated pre-existing untracked Graphify/vendor files intact. Do not replace the existing root Graphify shell-scoped graph with a monorepo-wide graph; avoid the previously troublesome encrypted/document path.
- Engram mirror is saved as observation `#255` using the independent local CLI with topic `odd/v0.9.4-opencode2api-tor-hardening/tasks`; the host still reports no authoritative runtime identity, so no agent-attributed MCP memory write was made.
