# Feature: v0.9.4 opencode2api update and Tor hardening

## Objective
Prepare the fork's v0.9.4 candidate with a current vendored opencode2api, preserve FreeCode's direct-first anonymous routing, make Tor startup/control safer and more reliable, prioritize the embedded browser in web-research prompts, restore Gentle AI in the selectable mode roster, and make ambient conversation backgrounds visibly render with or without motion enabled.

## Problem and why
The current embedded gateway is based on upstream opencode2api v1.3.5, while upstream v1.3.8 addresses free-model probe/manual-selection behavior and canonical session identity issues relevant to the recent no-model failures. The fork also has a Tor manager that treats an open SOCKS port as bootstrap readiness, exposes an unauthenticated local ControlPort, and disables adaptive circuit-timeout learning while forcing a five-second timeout. These behaviors can advertise a route before Tor is usable, let another local process control Tor, and reject ordinary slow circuits.

## Scope and constraints
- Work only on this fork. Public upstream source tag `v1.3.8` is the dependency baseline; do not edit, push to, or merge into the upstream repository.
- Preserve the local FreeCode anonymous-pool policy: every request starts on direct and advances to Tor only after a non-2xx response within the same request. Reapply and test it after source sync.
- Improve Tor ControlPort authentication and actual bootstrap readiness; remove the over-aggressive fixed circuit timeout and safely format Windows torrc paths where covered by tests. Preserve the long circuit dirtiness interval used for stable model streams.
- Restore Gentle AI as an explicitly selectable Web agent mode, adapting its fork preset to the current declarative Web bundle and protecting the shipped selector path with regression tests. Standard remains the default.
- Make the animated conversation ambient backgrounds perceptible in the shipped UI, including when `prefers-reduced-motion` is active; reduced motion must stop animation, not effectively hide the background. Add a rendered-style regression contract rather than only checking that keyframe names occur in a bundle.
- Diagnose Tor startup failures instead of discarding child diagnostics; never report bootstrap timeout when the daemon exited early, and show a safe actionable reason in the Tor overlay while preserving direct-only fallback and retry.
- Keep Tor's gateway SOCKS candidate stable after initial bootstrap failure, preserve the direct-first policy, and restore an unhealthy loopback SOCKS route with local probes without waiting 15 minutes or sending extra external checks.
- For web-research tasks, tell models to inspect and use the embedded `computer_use` browser before DeepSeek API search, with search fallback only when the browser is unavailable, blocked, or fails; preserve permission and untrusted-page boundaries.
- Do not inspect, close, restart, or kill unrelated processes. The user explicitly authorized generating and executing the local 0.9.4 one-click setup and confirmed FreeCode is closed before execution. Do not run a separate app launch or GUI smoke beyond any normal installer post-install action.

- The user re-authorized rebuilding and executing the local v0.9.4 installer to validate the background fix. Do not inspect, launch separately, close, restart, or otherwise interact with the user's app; before running the one-click installer, obtain confirmation that FreeCode is closed.

- FreeCode's direct-first anonymous retry behavior remains intact: first attempt uses direct; only a non-2xx advances to Tor in the same request.
- Tor is not marked ready until its ControlPort reports bootstrap `PROGRESS=100` and the SOCKS listener is usable; ControlPort commands authenticate securely; adaptive circuit timeout learning is enabled (no forced five-second cutoff); Windows paths with spaces are handled safely.

Tor failure leaves explicit direct-only mode intact.
- When Tor becomes ready after a failed start, the gateway retains the same SOCKS endpoint and rechecks a failed loopback SOCKS route within 10 seconds using only the SOCKS5 greeting; remote-proxy external checks retain their slower cadence. Direct stays first. Provider 401/403/API-key errors remain distinct from Tor transport errors.
- Local changes remain unpushed and untagged; no release is published. The local setup is generated and executed only after the user confirms FreeCode is closed.
